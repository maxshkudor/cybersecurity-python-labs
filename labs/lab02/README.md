# Лабораторна робота №2 — варіант 10

## Монітор термінів дії SSL/TLS сертифікатів

Програма читає список сертифікатів із JSON-файлу та перевіряє:

- скільки днів залишилося до завершення дії сертифіката;
- чи сертифікат уже прострочений або скоро завершиться;
- чи використано застарілий алгоритм підпису MD5, MD2 або SHA-1;
- чи довжина ключа менша за 2048 біт;
- скільки сертифікатів видано кожним центром сертифікації.

У програмі також є демонстрація ООП-моделі з першого завдання: користувач,
адміністратор, сесія, журнал аудиту та обліковий запис.

## Структура

```text
labs/lab02/
├── __init__.py
├── main.py                 # запуск команд demo та analyze
├── task1.py                # класи User, Admin, Session, AuditLog, UserAccount
├── task2.py                # аналіз сертифікатів і збереження звіту
├── README.md
└── data/
    └── certificates.json   # вхідні дані для варіанта 10
```

## Вимоги

- Python 3.10 або новіший;
- сторонні пакети для запуску програми не потрібні — використовуються модулі
  стандартної бібліотеки Python.

Якщо в кореневому `requirements.txt` репозиторію є Ruff, його можна встановити
командою:

```powershell
pip install -r requirements.txt
```

## Запуск

Усі команди запускайте з кореня проєкту — каталогу, у якому є папка `labs`.

### Демонстрація завдання 1

```powershell
python -m labs.lab02.main demo
```

Демонстрація показує успішний і невдалий вхід, перевірку email, дозвіл
адміністратора, завершення сесії після таймауту, вихід і записи аудиту.

### Аналіз сертифікатів

Запуск із типовими параметрами:

```powershell
python -m labs.lab02.main analyze
```

За замовчуванням програма читає `labs/lab02/data/certificates.json`, попереджає
про завершення строку протягом 30 днів і створює JSON-звіт
`labs/lab02/data/certificate_report.json`.

Приклад CSV-звіту з порогом попередження у 14 днів:

```powershell
python -m labs.lab02.main analyze `
  --certs-data labs/lab02/data/certificates.json `
  --days-warning 14 `
  --output-report labs/lab02/data/certificate_report.csv `
  --format csv
```

## Параметри `analyze`

| Параметр | Опис | Значення за замовчуванням |
| --- | --- | --- |
| `--certs-data` | Шлях до JSON-файлу з сертифікатами | `labs/lab02/data/certificates.json` |
| `--days-warning` | Попереджати, якщо до завершення строку залишилося не більше вказаної кількості днів | `30` |
| `--output-report` | Шлях до файлу звіту | `labs/lab02/data/certificate_report.json` |
| `--format` | Формат звіту: `json` або `csv` | `json` |
| `--log-level` | Рівень повідомлень: `DEBUG`, `INFO`, `WARNING` або `ERROR` | `INFO` |

## Формат вхідного JSON

Кореневим елементом файлу має бути список об'єктів. Кожний сертифікат має
містити поля `domain`, `issuer`, `validFrom`, `validTo`, `keyLength` та
`signatureAlgorithm`. Дати задаються у форматі `YYYY-MM-DD`.

```json
[
  {
    "domain": "example.invalid",
    "issuer": "Example CA",
    "validFrom": "2026-08-01",
    "validTo": "2026-11-29",
    "keyLength": 2048,
    "signatureAlgorithm": "sha256WithRSAEncryption"
  }
]
```

## Результати аналізу

У консолі для кожного сертифіката показуються домен, видавець, кількість днів
до завершення строку, статус, алгоритм підпису та виявлені проблеми. Статус
`EXPIRED` означає, що строк уже минув; `WARNING` — що знайдено проблему або
попередження; `OK` — проблем не виявлено.

JSON-звіт містить результати перевірки й підрахунок сертифікатів за видавцями.
CSV-звіт містить по одному рядку на кожний сертифікат.

## Обробка помилок

Якщо вхідний файл не знайдено, JSON некоректний, обов'язкові поля відсутні або
значення дат неправильні, програма виведе повідомлення про помилку в журнал і
завершиться з кодом `2`. Аргумент `--days-warning` не може бути від'ємним.
